# Телеграм-бот «Пульт КТПП»

Python, стандартная библиотека; отдельная служба `ktpp-bot` и локальная SQLite. Получает результаты и статистику из API портала, следит за доступностью сервера, отправляет напоминания об оплате VDS и вечерние итоги.

## Настройка владельца

Секреты задаются только в серверном `bot.env` с правами `600`:

- `TELEGRAM_TOKEN` — токен Telegram-бота;
- `PORTAL_URL` — адрес API портала;
- `PORTAL_PASSWORD` — пароль административного API;
- `OWNER_CHAT` — постоянный Telegram ID владельца; **или**
- `OWNER_CODE` — случайный секрет первоначальной настройки/восстановления: `/start <код>` в личном чате;
- необязательно `DB_PATH`, `WATCHDOG_LOG`, `AVATAR`.

**Без OWNER_CHAT и OWNER_CODE новый бот не достаётся первому постороннему, написавшему /start.** Владелец, уже записанный в SQLite прежней версии, сохраняется. Резервный код позволяет сменить владельца: храните его как пароль и меняйте после использования. Код не следует пересылать в общие чаты.

Бот принимает команды доступа и выдаёт данные только в личных чатах. Работа в группах запрещена.

## Доверенные пользователи

Владелец добавляет приглашение `/allow @username` или `/allow @username notify`. При первом входе незанятое приглашение однократно привязывается к Telegram ID. Далее доступ определяется этим ID, а не изменяемым именем.

- смена телефона в том же аккаунте не меняет ID и не требует переноса;
- новый аккаунт, которому досталось прежнее имя, автоматически доступ **не получает**;
- перенос на другой ID требует заявки `/start` и явного одобрения владельцем;
- `/deny @username` или кнопка удаления отзывают доступ;
- поддерживается добавление по числовому ID;
- пустые ID ожидающих приглашений не участвуют в рассылках.

**Права:** доверенным доступны меню, помощь, статистика, результаты и просмотр оплаты. Управление доступом, редактирование оплаты и общих уведомлений — только владельцу. Все ответы на команды приходят запросившему пользователю; уведомления — владельцу и пользователям с включённым `notify`.

Состояние ввода даты/срока изолировано по chat ID. Кнопки проверяют права повторно, а не доверяют наличию кнопки в сообщении. Даты статистики и итогов приводятся к Europe/Kaliningrad.

## Проверки

```bash
python3 bot/bot.py --selftest
python3 -m unittest discover -s tests -p 'test_*.py'
```

Самопроверка содержит 50 проверок; дополнительно 14 регрессионных тестов проверяют получателей сообщений, read-only кнопки, запрет административных действий, защиту от переназначенного username, перенос с подтверждением, bootstrap/recovery, изоляцию ввода, рассылку и часовой пояс. Используются SQLite в памяти и FakePortal; Telegram и рабочий API не вызываются.

`python3 bot.py --check-api` — **не офлайн-тест**: входит в рабочий API и обновляет оформление Telegram-бота. Запускайте осознанно на настроенном сервере, не в обычном CI.

## Эксплуатация

`deploy-bot.sh` — существующий скрипт обновления на VDS. Перед его использованием проверьте адрес сервера, резервную копию SQLite и конфигурацию секретов. Обычная проверка исходников ничего не развёртывает.

Команды пользователя: `/menu`, `/pay`, `/stats`, `/results`, `/id`, `/help`, `/cancel`. Управление владельца: `/access`, `/allow`, `/deny`.

Файлы `bot.env`, `bot/data/`, Python-кэш исключены из Git. Не храните резервные копии с токенами и паролями в публичном репозитории.
