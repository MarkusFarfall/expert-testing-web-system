# Экспертиза КТПП

Русскоязычная платформа тестирования на Next.js App Router, PostgreSQL и Drizzle ORM. Светлая адаптивная тема, локальные шрифты с кириллицей, собственная SVG-эмблема и архитектурная иллюстрация Калининграда. Tailwind CSS 4 и общие стили находятся в `src/app/globals.css`.

## Возможности

- Несколько независимых тестов (экзаменов): у каждого — собственный банк вопросов, импорт и статистика.
- Ввод ФИО без регистрации, выбор теста, общий режим с диапазоном по `numberquestion` и фильтром `blockid`.
- Выборочный билет: заданное число случайных вопросов из каждого блока, без повторений.
- Серверное сохранение каждого ответа, навигация по билету, необязательный таймер всего теста.
- Мгновенный результат, разбор ошибок, индивидуальный PDF и история текущего браузера.
- Административный CRUD вопросов и вариантов; ровно один правильный ответ.
- Атомарный импорт двух `.xlsx` в выбранный тест с проверкой схемы, дубликатов, ссылок и количества правильных ответов. `true_answer`: 1 — верный, 0 или пусто — неверный. Нумерация вида «N. » удаляется.
- Фильтрация общей статистики по ФИО, тесту и периоду, экспорт той же выборки в Excel и PDF.
- Реестр справочных документов с просмотром и скачиванием PDF.

## Данные

Подключение задаётся серверной переменной `DATABASE_URL`. Клиент Drizzle: `src/db/index.ts`. Таблицы и исходные названия колонок описаны в `src/db/schema.ts`.

При первом запросе создаётся учебный банк из **36 вопросов в 6 блоках**. Это демонстрационные материалы, а не утверждённая база для аттестации. Реальные файлы `TableQuestions.xlsx` и `TableAnswers.xlsx` загружаются администратором. Успешный импорт полностью заменяет банк. Уже начатые и завершённые тесты сохраняют свои снимки вопросов и не меняются при редактировании банка.

Вопросы, ответы, попытки, результаты и административные сессии хранятся только в PostgreSQL. Cookie эксперта содержит случайный идентификатор, а не ФИО или ответы. Чужие результаты нельзя получить, просто зная ФИО или ID попытки.

## Первый вход администратора

Откройте `/admin`. Если пароль ещё не настроен, задайте его при первом входе. В базе сохраняется только солёный scrypt-хеш. После выхода потребуется установленный пароль; сессия действует 24 часа, попытки входа ограничиваются.

Альтернатива: задайте секретную серверную переменную `ADMIN_PASSWORD`. В этом случае экран первоначальной настройки не показывается. Не добавляйте пароль в клиентский код или переменные `NEXT_PUBLIC_*`.

**Перед открытием публичного доступа обязательно настройте административный пароль** либо установите `ADMIN_PASSWORD`. Для эксплуатации также необходимы HTTPS, резервное копирование PostgreSQL, утверждённая политика обработки данных и организационные правила аттестации. Система не присваивает квалификацию автоматически и не задаёт произвольный проходной балл.

## Импорт

Первая строка первого листа содержит заголовки с точным регистром:

- Вопросы: `Id`, `question`, `blockid`, `numberquestion`.
- Ответы: `Id`, `answer`, `question`, `true_answer`, `numberanswer`.

Идентификаторы и номера — положительные целые числа. `true_answer` — `1` для верного варианта; `0` или пустая ячейка — неверный. Уникальность Id нужна только внутри файла: система сама переназначает внутренние идентификаторы. У вопроса не менее двух вариантов и ровно один верный. Размер каждого файла — до 10 МБ, до 10 000 вопросов и 50 000 ответов. Формулы не поддерживаются: замените их значениями. Образцы доступны в панели администратора.

При ошибке показывается полный доступный отчёт (до 150 пунктов), запись не выполняется. Можно скачать текстовый отчёт об ошибках.

## Запуск и проверка

Установите зависимости, настройте `DATABASE_URL` и подготовьте PostgreSQL. После начальной подготовки окружения примените схему командой `npx drizzle-kit push`.

Обязательная проверка проекта:

1. `npx next typegen`
2. `npm exec tsc -- --noEmit --pretty false`
3. `npm run build`

В управляемом окружении финальный запуск выполняется инструментом `build_and_start`, включая `/api/health`. Для обычного локального развёртывания доступны стандартные команды Next.js из npm-скриптов.

## Приёмочные проверки

Сценарий `scripts/acceptance.mjs` рассчитан на предустановленный учебный банк и работающий сервер. Он проверяет мобильное прохождение, сохранение после обновления страницы, изоляцию результатов, таймер, административный CRUD, невалидный и валидный импорт, сохранность исторических снимков, фильтры, Excel/PDF, документы и адаптивность 320/390/768/1440 px.

Требуется установленный Chromium для Playwright. Запуск: `node --experimental-strip-types scripts/acceptance.mjs`. По умолчанию используется `http://localhost:3000`; иной адрес задаётся в `TEST_BASE_URL`. Проверка восстанавливает исходный банк и удаляет собственные попытки. Если доступ администратора создан самим тестом, он тоже удаляется. Для проверки заранее настроенного администратора нужна серверная `ADMIN_PASSWORD`. Не запускайте демонстрационный приёмочный сценарий на рабочей базе с пользовательскими данными.

## Деплой

Vercel (проект `expert-testing-web-system`, корень репозитория) + Supabase PostgreSQL
(проект `ktpp-expertiza`, eu-central-1). Схема применяется миграциями:
`supabase db push` (SQL в `supabase/migrations/`). На Vercel задана `DATABASE_URL`
(transaction pooler, порт 6543). Вход администратора: `/admin`, пароль задаётся
переменной `ADMIN_PASSWORD` или при первом входе (хранится scrypt-хеш в `portal_settings`).
